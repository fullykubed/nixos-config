# Bun Tools

This repo uses [Bun](https://bun.sh/) with [bun2nix](https://github.com/nix-community/bun2nix) for building TypeScript tools reproducibly within Nix.

## Project structure

A Bun tool lives as a subdirectory inside its parent module:

```
modules/common/my-module/
├── default.nix          # Parent module (imports the tool)
└── my-tool/
    ├── default.nix      # Nix derivation
    ├── package.json
    ├── bun.lock
    ├── bun.nix          # Generated by bun2nix
    ├── tsconfig.json
    └── src/
        └── main.ts
```

## Setting up a new tool

### 1. Initialize the project

```bash
cd modules/common/my-module
mkdir my-tool && cd my-tool
bun init
```

### 2. Add dependencies and write code

```bash
bun add some-library
bun add -d @types/bun
```

Write your tool in `src/main.ts`.

### 3. Generate the lockfile and Nix deps

```bash
bun install           # generates bun.lock
bun2nix               # generates bun.nix from bun.lock
```

`bun.nix` is an auto-generated file that pins every dependency to a specific URL and hash. Never edit it manually — always regenerate with `bun2nix`.

### 4. Create the Nix derivation

Bun tools should be compiled into single-file standalone executables using `bun build --compile`. This embeds the Bun runtime, your code, and all dependencies into one binary with no external runtime needed.

```nix
# my-tool/default.nix
{ pkgs, lib, ... }:
let
  bun2nix = pkgs.bun2nix-cli;
in
pkgs.stdenv.mkDerivation {
  pname = "my-tool";
  version = "1.0.0";

  src = ./.;

  nativeBuildInputs = [
    pkgs.bun
    bun2nix.hook
  ];

  bunDeps = bun2nix.fetchBunDeps {
    bunNix = ./bun.nix;
  };

  buildPhase = ''
    runHook preBuild

    bun build --compile \
      --minify \
      --sourcemap=none \
      --bytecode \
      --target=bun-linux-x64 \
      --outfile my-tool \
      src/main.ts

    runHook postBuild
  '';

  installPhase = ''
    runHook preInstall
    mkdir -p $out/bin
    cp my-tool $out/bin/
    runHook postInstall
  '';
}
```

Key parts:

- **`bun2nix.hook`** — installs `node_modules` from the pre-fetched deps during the build, with no network access needed
- **`fetchBunDeps`** — reads `bun.nix` to fetch all dependencies as fixed-output derivations
- **`bun build --compile`** — produces a standalone executable with these flags:
  - `--minify` — reduces binary size by minifying the bundled code
  - `--sourcemap=none` — omits source maps for smaller output
  - `--bytecode` — pre-compiles to bytecode for faster startup
  - `--target=bun-linux-x64` — targets Linux x86_64

### 5. Wire it into the parent module

```nix
# my-module/default.nix
{ config, pkgs, ... }:
let
  myTool = pkgs.callPackage ./my-tool { };
in {
  home-manager.users.${config.username} = {
    home.packages = [ myTool ];
  };
}
```

## Passing environment variables

Since compiled binaries are standalone, use `makeWrapper` to set environment variables on the compiled output:

```nix
nativeBuildInputs = [
  pkgs.bun
  pkgs.makeWrapper
  bun2nix.hook
];

# ... after buildPhase compiles the binary ...

installPhase = ''
  runHook preInstall
  mkdir -p $out/bin
  makeWrapper ./my-tool $out/bin/my-tool \
    --set CHROMIUM_PATH "${pkgs.chromium}/bin/chromium" \
    --set MY_CONFIG_PATH "/run/agenix/my-secret"
  runHook postInstall
'';
```

## Multiple binaries

Compile each entrypoint separately:

```nix
buildPhase = ''
  runHook preBuild

  bun build --compile --minify --sourcemap=none --bytecode \
    --target=bun-linux-x64 --outfile my-tool src/cli.ts

  bun build --compile --minify --sourcemap=none --bytecode \
    --target=bun-linux-x64 --outfile my-tool-server src/server.ts

  runHook postBuild
'';

installPhase = ''
  runHook preInstall
  mkdir -p $out/bin
  cp my-tool my-tool-server $out/bin/
  runHook postInstall
'';
```

## Updating dependencies

```bash
cd modules/common/my-module/my-tool
bun update           # update bun.lock
bun2nix              # regenerate bun.nix
```

A pre-commit hook verifies that shared dependencies across all `package.json` files in the repo use consistent versions. If two tools depend on the same package, they must pin the same version.

## Local development

During development, you can run the tool directly without a Nix build:

```bash
cd modules/common/my-module/my-tool
bun install
bun run src/main.ts
```

This is faster for iteration. Run a full Nix build to verify it works in the sandboxed environment before committing.
